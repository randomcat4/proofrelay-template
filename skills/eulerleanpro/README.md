# eulerleanpro

版本 0.1.0 · 重大数学成果的独立 Lean 形式化 Skill

这不是 Lean 安装包、后台 Agent 服务或自动科研平台。它是一套可直接交给 coding agent 的模块化指令、角色提示词、工作流、模板和回归场景。

## 解决什么问题

输入是一项重大进展、完整候选证明、论文，或需要接手的 Lean 工程。输出不止是“编译通过”，还应包括数学家可独立阅读的结果说明、形式化路线图、自然语言—Lean 对照和经实际代码提取的证明依赖 DAG（提取能力不足时如实报告）。

与轻量模式分工：`math-theorem` 在探索中临时核验承重步骤；`eulerleanpro` 独立组织一个成果的系统形式化。无需安装 `math-ultra`。本包不包含用户私库的代码、路径或研究材料。

## 安装

ZIP 内只有一个顶层目录 `eulerleanpro/`，唯一入口是该目录的 `SKILL.md`。不要只复制这一个文件；其余目录是实际依赖。

以下位置适用于本地 coding-agent 会话；云端会话的技能启用方式可能不同，需按宿主当前文档操作。

Codex 项目级安装：把整个目录复制到项目的 `.agents/skills/eulerleanpro/`。
Claude Code 项目级安装：复制到 `.claude/skills/eulerleanpro/`；个人级可放 `~/.claude/skills/eulerleanpro/`。
其他支持 Agent Skills 的宿主使用其实际技能目录；不识别 Skill 时，让 agent 显式读取整个包内的 `SKILL.md` 入口，随后按引用读取必要模块。

安装时先检查目标目录是否已存在，保留旧版，不覆盖用户修改。无需执行安装脚本、启动服务或设置 API key。具体宿主路径以当前产品文档为准，官方来源见 `SOURCES.md`。

### 第一次调用

```text
使用 eulerleanpro。当前仓库包含我们准备形式化的重大结果。
先读取已有研究材料、Lean 工程和相关 Issue/PR，核对完整目标及工具链。
先给最小接入建议与形式化路线图，不迁移旧材料，不更换工具链，不发布网站。
在已授权的工作范围内，用真实子智能体分担陈述、证明、语义审查和可读说明。
```

已经有精确任务时不必重复初始化：

```text
使用 eulerleanpro 接手 PR #编号。
优先修复现有形式化；保留数学陈述，继续原 PR。
交付能独立阅读的数学证明说明，并区分已验证范围与剩余缺口。
```

## 包的组织

| 目录/文件 | 用途 |
|---|---|
| `SKILL.md` | 触发、路由、关键约束；不是一本塞满全部内容的手册 |
| `DEPENDENCIES.md` | 内部模块前置条件、角色输入输出、外部能力与降级路线 |
| `workflows/` | 首次接入、主流程、恢复/修复、审查/交付 |
| `agents/` | 六种可委派角色提示词；由宿主实际创建子智能体 |
| `references/` | Lean 实操、语义、人类可读性、GitHub、Blueprint 和图的具体规则 |
| `assets/templates/` | 可以选择性复制的任务、结果、审查和 CI 模板 |
| `examples/` | 一个小型示范的 Lean 与可读数学说明；不是重大成果样例 |
| `tests/` | Skill 包结构测试与行为回归场景，不是科研控制器 |
| `SOURCES.md` | 集中列出照搬/改写/仅参考的上游来源及本包改动 |
| `LICENSE`, `licenses/` | 保留的许可证与第三方声明 |
| `VALIDATION.md` | 本次实际检查结果和未验收项 |

## 四项有意的取舍

1. 不维护第二套任务/真值账本。Issue 管工作，PR 管变化，Lean 管编译，文档解释数学。
2. 路线图可以由人和模型规划；只有真实证明依赖称 DAG。两者不强行双向同步。
3. Blueprint 是推荐的成熟文档工具，不是前置强依赖。原项目用传统 LeanBlueprint 时继续使用；没有时可先交付 Markdown/LaTeX，再单独接入网站。
4. 角色可按需组合，但候选作者与最终独立审查者不能在同一上下文自审。工具能力不够就说明，不靠角色扮演补齐。

## 最小外部条件

开展真实证明需要当前项目对应的 Lean、Lake 和库依赖。使用 GitHub 需要已授权工具或 `gh`；并行需要宿主真实子智能体；交互网站需要项目兼容的 Blueprint。所有提示词与模板本身均已随包提供，不需再下载其他 Skill 才能读懂。

没有 Lean 时可以整理来源、审查陈述和撰写路线图，但只能交付未编译草稿。没有 GitHub 时可在本地分支准备成果，不声称已创建 Issue/PR。

## 检查本包

```bash
python -m unittest discover -s tests -v
```

需要 Python 3.10+ 标准库。它只检查安装包、引用、模板和测试数据，不校验数学、不操作研究项目、不调用网络。

行为回归见 `tests/README.md`。当前版本没有在真实宿主中完成多智能体端到端验收，示例 Lean 与 Blueprint 网站也未在本次打包环境编译。准确范围见 `VALIDATION.md`。
