# 真实委派与并行工作

## 不伪造能力

使用宿主实际暴露的子智能体/新会话调用，遵守其权限与并发上限。不写固定的 `spawn_agent(...)` API 假装所有宿主相同；不默认六槽或六十四槽，也不引入后台调度代码。
当前工具若没有委派能力，明确顺序执行。独立性不足的最终审查保留待办，不用“现在扮演新审稿人”补票。

## 分工按数学边界而非人数

先分离来源/定义、陈述审查、证明与解释。只启动有独立输入和验收物的任务。
同一文件的密集修改一般串行；不同模块可以并行，稳定接口后再集成。
来源阅读、已明确声明的不同引理证明、已有候选的叙述草稿可以并行。陈述未确定时，不浪费多个证明者去证明不同理解的题目。

## 每次派发必须给的信息

使用 `assets/templates/task-brief.md`，填写项目根、分支/工作树、任务 Issue（存在时）、确切目标与声明、允许修改的文件、只读依赖、禁止改动、需要加载的模块、期望成果和用户预算。
把重要项目边界显式传给子智能体，不假定自动继承。只给它必要的 Skill 模块，不传全库和完整聊天史。
每个任务在独占目录/工作树或清楚划分的文件内写入。不撤销、清理、暂存或提交其他人的改动。

## 角色输入输出

陈述者拿到原文与现有定义；交付 Lean statement 和解释。
语义审查者拿到同一原文、实际 statement 和定义，不给作者的自我评定；交付匹配/差异/材料不足。
证明者拿到经审查接口、搜索入口和依赖；交付实际候选与编译结果、数学骨架、未闭合 goal。
叙述者拿到原文、statement 和实际 proof；交付自包含数学说明和对应关系，不修补证明。
最终审查者从集成版本独立读取材料并按需重跑；不是收集作者“PASS”就放行。

## 交叉依赖

上游返回新接口后先集成/读取并编译，再继续依赖它的工作。下游可以先用可见占位探索结构，但必须标清依赖未证。
接口改变时只通知受影响任务并检查调用点；不重启所有 agent，也不维护第二套事件总线。
多个失败路线汇到同一缺口时先判断共同数学障碍，允许修订路线图；不能直接改原始结论。

## 收回成果与接手

工作者返回实际文件、PR/分支（有则给）、声明、命令结果、剩余目标和建议下一步；不要求冗长逐步聊天日志。
一般修补可复用作者上下文，最终独立审查使用新上下文。
任务被中断后先读实际进展，不假定任务仍在运行；主实例可根据当前授权重派最小未完成工作，避免重复提交。
