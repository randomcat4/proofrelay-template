# 人类可读成果是交付的一部分

改写来源：StatLean 网站贡献规则（Apache-2.0）及 CBirkbeck/mathlib-quality 的蓝图写作约定（MIT）。本文件经过中文改写与范围调整；来源、保留许可证及修改说明见 `SOURCES.md`。

## 阅读者假设

读者有相应领域的数学训练，但未必懂 Lean，也没看过聊天记录。他应能直接打开某个结果页，看懂结论、条件、证明结构和与原文的关系。

最小结果页见 `assets/templates/result-page.md`。可用现有 Blueprint、Markdown 或 LaTeX 实现，不要求搭建一个复制 StatLean 的 React 网站。

## 每个重要结果至少说明

1. 研究意义与精确数学陈述。对象、全部实质假设、结论、边界和记号在本页可见。
2. 数学证明主线。每个承重推理为什么成立，关键引理完成哪一步；可以跳转详细引理，但不能用“见 Lean”代替论证。
3. 自然语言到 Lean 的对应。实际声明和完全限定名、文件、假设对照；声明必须从实际源代码读取，不靠记忆另写一份。
4. 表示差异与来源。数据结构、索引、归一化、定义域、加强/弱化及等价桥梁；原文版本和定理/页码。
5. 当前机械验证范围、未覆盖结果和可复现命令。只说实际执行过的内容。

人类说明中的未闭合步骤明确标注“待证”。叙述者不能为让故事顺滑补出作者从未建立的引理。

## 写数学，不写 Lean cosplay

坏：“通过 `rw` 后 `simp`，再 `omega`，所以主定理成立。”
好：“先把两侧展开为同一组平方项；由平方非负得到上、下界，再用绝对值的双边界刻画合并结论。”

去掉 universe、coercion、实例解析等语法，但保留其数学内容。`CompactSpace`、`CompleteSpace`、`FiniteDimensional`、可测性、非空性、有限性可能正是重要假设，不能因它写成类型类就删掉。
自然语言写“R 是交换环”等数学描述，不机械抄 `[CommRing R]`。若条件在章首定义，结果页至少概括并链接，不能只写“在上面的条件下”。

## 不把定理编号当内容

“满足式 (3.7)”不足以自包含。写出具体条件，编号仅作定位。
Lean 名称不替代数学对象；每个新记号先定义。原则是一个结果页能独立读懂，不是每页重复全本背景教材。

## 证明的层级

先给一段概览，再给可跟随的主证明。技术性 helper 放附注/链接；核心新思想不能压成两句“标准方法”。长证明允许分章，章节必须交代输入与输出。
不强制逐行翻译 tactics，也不把所有原文逐页复制进去。引用原文注意许可，尽量用自己的数学表述。
用户要求审计原证明时，逐项说明形式化改用了什么方法；换一种证明只认证陈述，不自动认证原论证。

## 假设对照（无需自制数据库）

在结果页用短表列：数学条件 → Lean binder/definition → 解释或差异。
如项目已有 StatLean 式结果数据和双栏网页，遵守其 schema 与生成流程；优先从 Lean 源生成签名，不再手工同步第二份状态。
不为了 hover 效果增加一个新前端工程。现有 Blueprint 的声明链接、源码页和数学叙述已可作为第一版。

## 可读性验收

让独立审查者先不看 tactics，读说明并复述：命题是什么、为什么成立、关键引理在哪里用、哪些仍未证。
再对照实际 Lean 类型和证明。若文字悄悄漏掉可积性、把几乎处处写成处处、把条件版本写成无条件，这不是排版问题，而是语义失败。
不能只给“可读性 9/10”分数；指出具体缺陷和最小修改。

## 原文问题的表述

区分歧义、明确错误和形式化困难。证据不足时说不足；确认反例时准确报告反例和影响范围。
不照搬“已发表原文通常没错”的先验，也不为了宣传把形式化差异写成推翻整篇论文。
