# 独立审查与交付

前置：当前候选已集成到清楚的分支/PR；读取 `references/acceptance.md`、`references/readability.md`、`references/graphs.md`。

1. 固定本轮检查的实际 Git 版本或 PR 当前提交，仅使用 Git 自身定位，不建立额外摘要账本。
2. 由独立上下文阅读原文与 Lean 声明、定义，检查实际依赖和构建覆盖；没有独立上下文能力就说明待独立审查。
3. 运行合理的构建和公理/占位检查。发现问题给首个实质缺口与复现入口，不在同一“独立审查”动作里悄悄改稿再自批。
4. 作者定向修订，重新检查受影响范围。语义变化重新交语义审查。
5. 让叙述审查者先看数学说明再对照 Lean：是否完整交代前提、证明主线和条件性？不能只问 agent “可读吗”。
6. 检查图的来源、范围和标题，网页/文档构建是否实际执行。图缺失可单列未交付，不能画一个猜测图充数。
7. GitHub 上提交真实 Review 或有角色说明的 comment；不能伪造其他账号批准。
8. 返回分项结论与链接。未授权合并/发布时到待审 Draft PR 或本地成果为止。

目标不是得到全绿标签，而是让接手者知道什么实际成立、为什么，以及还缺什么。
