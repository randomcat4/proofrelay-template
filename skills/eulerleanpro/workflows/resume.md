# 接手、恢复与修复

前置：当前项目路径和授权；读边界、环境、相关 PR/Issue，不假设旧摘要正确。

1. 查当前分支、未提交改动、旧 PR/Review、CI 和主目标。保留其他人的工作，不清理未知文件。
2. 确认真实完成范围：哪些 Lean 文件已纳入 build，哪些只存在草稿，哪些来源/语义仍未审。
3. 若用户只要求修复编译，不扩展为全篇重构，不改数学陈述，不批量迁移文档。
4. 若旧 Blueprint 是绿色但源变更了，重建并重新检查相关目标；缓存页面只当历史快照。
5. 读取最近精确 blocker，检查是否仍成立。优先继续已有分支/PR，不为同一任务重新建一套 Issue。
6. 判断哪些工作可以独立续做；任务曾标为活跃不代表对应进程仍存在。读回实际产物后再重派。
7. 有源陈述变化、依赖版本漂移或定义语义修改时，重新审查受影响部分；普通 proof 修复只重查相关内容。
8. 实施后交付实际差异、构建结果、未解决项与下一步，不把本次修复扩大描述成全工程验收。

不需要 checkpoint 数据库。Git、Issue、PR、源文件和可读数学说明已是接手材料。
