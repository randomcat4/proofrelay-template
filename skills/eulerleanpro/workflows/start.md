# 首次启动 / 接入已有项目

前置：已读项目规则、`references/boundaries.md`、`references/environment.md`。

1. 读当前目标和原文，确认是重大结果形式化而非轻量承重检查。复用用户已有信息。
2. 只读查看仓库、分支、未提交改动、Lean/Lake 版本、现有库结构、Blueprint 和相关 Issue/PR。
3. 简短报告：已有可用资产、实质缺口、建议沿用的结构、需要增改的最少文件。不要先建一套空框架。
4. 依 `references/statements.md` 明确来源目标和形式化范围。没有原文时只处理能确定的材料，标记不足。
5. 任务已授权实施的常规增量直接在独立分支开展；重大目录迁移、工具链升级、公开发布和费用服务另行确认。不因协议形式要求用户反复批准已经批准的工作。
6. 选择若干重要声明作为第一批目标，写准确类型和最小文档；交独立语义审查。不要一次生成整篇未编译 Lean。
7. 使用 `assets/templates/roadmap.md` 思路写一份形式化路线图。关联已有 Issue；确实需要分工才创建新 Issue。
8. 进入 `workflows/formalize.md`。启动报告只写有用事实，不把所有模板原样贴给用户。

完成启动的判据：主目标可定位、工作范围清楚、工程状态已观察、至少知道下一项能实际开展的数学任务。不是“目录都建好了”。
