# 研究问题搜索与低垂果实筛选

这个模式寻找的是“剩余证明义务”，不是最有名的猜想。成功产物是一份状态核验过、可证伪、可验证、值得投入的短名单；不是模型声称某题容易。

## 基本原则

1. **硬门先于评分。**状态不明、陈述含糊、来源不可靠或没有验证计划的候选先挂起，不能靠高分补救。
2. **分母必须保留。**记录看过多少候选、为何淘汰、花了多少工作单元。只保存成功者会制造幸存者偏差。
3. **搜索与证明分开。**筛选实例可以查文献；独立证明实例只接收冻结命题和经审计的公共背景。短名单中的“高潜力”不是数学证据。
4. **真假保持中立。**默认同时允许证明和反例。不得把“假定肯定答案存在”写进发现流程。
5. **验证器优先。**能自动执行、形式化或由专家快速核查的证书，比模型自信、路线投票和叙述流畅更有价值。
6. **搜索差异，不搜索同义改写。**按相邻定理、表示方式、局部到全局结构和证书类型区分候选。
7. **先承诺价值，再看答案。**在运行模型前写下为什么问题有趣、预期贡献等级和禁止的平凡解释，避免成功后移动价值门柱。

## 六槽搜索编排

总并发包含主实例，最多六槽；默认不全部启动。

- **主实例：**定义范围、维护候选分母、执行硬门和晋级。
- **来源与状态审计：**定位原始问题、前向引用、作者更新和更强结果。
- **相邻定理与表示翻译：**构建“已知定理 → 剩余义务”链，寻找图/流/码、离散/连续、原始/对偶等翻译。
- **廉价证伪与小规模探针：**找最小反例、有限模型、SAT/SMT/ILP/计算实验或极端参数。
- **证明义务压缩：**判断缺口能否缩成一两个严格弱于原问题的关键引理。
- **独立怀疑者：**检查状态、评分和验证器是否由同一套模型假设循环支持。

状态审计结束后即可回收其槽位。只有硬门通过且出现可检查信号的候选，才启动证明义务压缩或更多探针。

## 搜索流程

### 1. 冻结搜索范围

使用 `assets/run-templates/search-scope.md` 写清：

- 数学领域与允许的交叉领域；
- 接受证明、反例、改进常数还是算法构造；
- 目标强度与最长期望证书；
- 事前价值标准：什么结果即使由人完成也值得记录、发表或继续研究；
- 文献截止日期、允许的数据库和形式化工具；
- 候选上限、工作单元上限和最多晋级数；
- 哪些问题因风险、权限或用户偏好排除。

### 2. 收集候选并记录原始出处

来源优先级：

1. 原论文的 `Conjecture`、`Problem`、`Question`、`Future work`；
2. 作者维护的开放问题清单、正式 workshop 问题集和学会资源；
3. 带固定语义的形式化研究基准；
4. 预印本版本差异、已知端点或参数族中的孤立空洞；
5. 聚合站只作线索，不能作为“仍开放”的最终证据。

常用检索模式包括：`remains open`、`only remaining case`、`except when`、`sharp constant`、`endpoint case`、`would follow if`、`it suffices to prove`、`we do not know whether`。同时搜索等价术语、邻近领域词汇和反例表述。

每个候选立即写入 `candidate_ledger.md`；不能等看到成功后再补分母。

同时写 `意图契约`：原作者或领域通常想问什么、哪些字面解释虽形式成立却数学上空洞、部分回答是否算成功。若无法可靠恢复意图，状态必须是 `STATUS_UNCERTAIN`。

### 3. 状态硬门

候选只有同时满足以下条件才进入评分：

- 有可点击的原始或作者维护来源；
- 精确陈述、量词和边界能够冻结；
- 前向引用、作者页面或权威数据库未显示已解决；
- 已知结果与真正缺口能分开写出；
- 原问题的意图契约和禁止的平凡解释已写明；
- 至少有一种廉价证伪或最终验证计划；
- 不是改名后的经典定理，也不是明显依赖更著名的等价难题。

状态使用四值：`VERIFIED_OPEN`、`STATUS_UNCERTAIN`、`SOLVED_OR_OCCUPIED`、`MALFORMED`。后三者不能进入深搜；`STATUS_UNCERTAIN` 保留在账中等待人工或作者确认。

### 4. 把整题压缩成证明义务

对每个通过硬门的候选写一条依赖链：

```text
已知相邻定理 → 已有约化 → 尚缺的局部/全局兼容条件 → 目标结论
```

优先寻找这些结构信号：

- 一般对象可约化到有界度、有限局部类型或临界参数；
- 已有流、着色、松弛、势函数、稳定性或近最优界，目标只差整数化、粘合或端点；
- 目标含 exact-k、奇偶、守恒或有限群结构；
- 局部合法构造可枚举，而全局障碍可能进入线性系统、核/余核或上同调；
- 通用全称命题可被一个短显式构造证伪；
- 连续代理、离散代理或跨领域表示能显著压缩依赖深度。

若“关键引理”与原命题等价或更强，标为 `EQUIVALENT_BLOCKER`，不能因换了表示而晋级。

### 5. 廉价探针

探针只负责产生信息：

- 枚举最小对象和退化边界；
- 搜索显式反例或极值构造；
- 对局部 gadget、恒等式和候选不变量做计算检查；
- 在已知答案的简化/热身题上测试表示是否有效；
- 检查引用定理的假设和约化可逆性。

有限结果不能证明一般命题，但可以淘汰错误候选、揭示正确前提或提高验证器质量。

验证采用阶梯，不强迫所有领域立即 Lean 化：

```text
最小反例/小例检查
→ 专用可执行验证器
→ 把长证明拆成前提—结论—依赖块的独立审计
→ Lean/Coq 等内核检查
→ 领域专家核对题意、归属和新颖性
```

任一层发现致命问题即停止放行。形式内核通过仍需自然命题—形式陈述忠实性审计；只选择容易形式化的题会造成领域偏差，必须在候选账中披露。

### 6. 评分只在硬门之后使用

每项取 `0/1/2`，分数只用于同一候选池内排序，不解释成成功概率：

正向信号：

- 相邻定理强度；
- 缺口压缩程度；
- 局部有限性或构造性；
- 反例/证明证书的可执行验证强度；
- 预期证书短度与形式化准备度；
- 表示错位或跨领域翻译机会；
- 数学意义与结果可解释性。

“数学意义”必须引用搜索前写下的价值标准；不能因为模型碰巧给出答案，事后把原本无关紧要的候选抬高。

风险扣分：

- 等价难题或循环依赖风险；
- 需要新建整套理论的依赖深度；
- 语义、量词或边界仍有歧义；
- 证明链长而脆弱，缺乏局部检查点；
- 文献状态或新颖性仍不确定。

不要设置跨领域统一的魔法阈值。主实例结合硬门、相对排序和预算，最多晋级一至两个候选。

对策展等级较高的候选，可额外记录：是否至少有两名专业数学家认真尝试、若由人完成能否达到标准专业期刊价值、普通计算资源能否在约一小时内核验证书。这些是可信度信号，不是所有低垂果实的强制条件；冷门问题可能恰恰缺少多人尝试。

### 7. 晋级与停止

候选状态：

- `REJECTED`：已解决、命题畸形、明显反例或不在范围；
- `HOLD`：状态或语义待人工确认；
- `SCOUT`：硬门通过，获得一个廉价探针单元；
- `DEEP`：产生显式构造、严格弱关键引理或明确闭合路径，可新开证明运行。

一个探针单元没有新对象则暂停；两个单元仍只有直觉则淘汰。多候选都依赖同一开放引理时，把该引理升级为新的候选，而不是继续给原题重复采样。

六槽限制会牺牲最困难尾部。补偿方式是对已经产生强证据的候选增加串行批次，而不是一开始增加同质并发；每个新增批次都要报告边际收益和验证成本。

### 8. 短名单输出

`shortlist.md` 必须包含：

- 候选总数、各状态数量和总工作单元；
- 每个晋级候选的冻结陈述草案；
- 事前价值承诺和意图契约；
- 最强相邻定理和真正剩余义务；
- 最快证伪测试、最终验证器和主要风险；
- 为什么它优于被淘汰候选；
- 下一轮最多两至三条高差异路线。

短名单不得写“很可能为真”作为晋级理由。完成短名单后结束发现运行；证明使用新的目录和上下文。

### 9. 搜索系统自身的评测

发现器不能只用“最后有没有碰巧解出一道题”评估。每次搜索在开始前冻结候选池、检索截止日、人工工时和模型工作单元，在 `search_metrics.md` 同时记录：

- 收集候选总数与最终公开的完整分母；
- 开放状态、原题意图和归属核验的正确率及待定率；
- 误收已解决题、误改题意、误认新颖性和误放行错误证明的次数；
- `REJECTED/HOLD/SCOUT/DEEP` 的数量、理由及人工推翻次数；
- 每个候选的模型工作单元、检索调用和人工审计时间；
- 选择不晋级是否正确，即“诚实弃权”能力；
- 形式化可覆盖候选与原候选池的差异，防止只在易形式化子域报喜；
- 在固定预算下得到多少经独立验证且有事前价值承诺的结果。

评测分三层：先在已知结局但对运行者隐藏的历史截面上测状态与语义核验；再在有隐藏证明或反例的冻结基准上测证明审计；最后才在真正开放题上测新发现。报告 `pass@budget` 和完整成本，不用增加采样次数后的 `pass@N` 掩盖效率。真实开放题可以没有短名单；空结果优于伪造低垂果实。

## 研究依据与边界

- Terence Tao 的 Equational Theories Project 展示了适合机器协作的中等规模、形式可验证问题族；重点是完整问题图和真/假双向证书，而不是只挑名题。
- Tim Gowers 对近期 AI 数学工作的判断是：模型尤其可能发现人类漏掉的短论证，但专家仍需判断问题、验证结果和区分有趣与无趣观察。
- Daniel Litt 的 Problems I Like 为候选预先记录背景、兴趣和难度；这种事前承诺能防止 AI 成功后重新解释问题价值。
- DeepMind 的 Aletheia 全量处理 700 个当时标为开放的 Erdős 问题时，大量“技术正确”答案没有回答原数学意图；这说明语义忠实性、旧文献重发现和公开分母都必须成为一等审计对象。
- First Proof 第二批明确指出，目前还没有可信实验测量系统能否提出有趣猜想、定义或框架；其证明评测中，系统在结构接近已有文献时表现最好，并经常把最难步骤写成“标准论证”。所以“会证明给定命题”不能外推为“会找到值得证明的命题”。
- ProofCouncil 显示新鲜上下文的最终批评者能纠正有状态批评者的路径依赖，但也出现了未核实外部技术断言而误放行的案例；多角色调用成本显著高于单次强模型，故委员会和计算节点应由具体义务触发。
- FunSearch 与 AlphaEvolve 的可迁移部分是“生成—自动评估—保留最优—继续变异”；它们成功的前提是存在强、可执行的外部评估器，不能照搬到只有模型自评的开放证明。
- Co-Scientist 的相似度/邻近性代理适合候选去重，排名赛只提供相对排序，不能作为数学真值或新颖性证据。
- Formal Conjectures 一类基准说明形式化陈述既是验证器，也是语义审计对象；项目中对误形式化的持续修订说明，形式化通过不能替代对“形式陈述是否忠实于原问题”的人工检查。
- FrontierMath Open Problems 一类策展标准强调：至少两名专业数学家认真尝试、结果有专业价值、证书能在普通计算资源上快速验证；这类事前门槛比模型自评分更适合建立果园。
- Leiden Declaration 强调透明、归属、独立验证和数学理解。搜索系统必须公开失败分母、工具使用和先行工作，不能只发布胜例。

这些依据指导流程，不保证任何候选是低垂果实。
